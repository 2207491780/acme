# 原型增量四：发布工程 / 环境 / 稳定性 / 集成四域（R·H·S·G·X）

日期：2026-11-12
关联：`2026-11-12-02-prototype-zone.md`（落点）、`2026-11-12-03-prototype-visualization.md`（零依赖纪律）

## 背景

用户要求「再增加一些别的原型设计页，考虑尽量全面」。对 29 项既有原型做覆盖面盘点后，识别出四个尚未成域的方向 + 一个横向缺口。

## 决定

新增 10 项（registry 四个新域「发布工程域 / 环境域 / 稳定性域 / 集成域」+ 横向 X1）：

| ID | 名称 | 核心口径 |
|---|---|---|
| R1 | 发布就绪度检查 | Go/No-Go 六项门禁（构建/测试/审批/产物/窗口/回滚），prod 冻结期与缺签为硬阻塞；评分=通过占比 |
| R2 | 新建发布单向导 | 四步向导形态（与正式模态框互补探索），提交后接 R1 口径 |
| R3 | 制品库 | 跨单产物聚合、来源追溯、检索；保留策略为成熟化占位 |
| R4 | 版本对比 | 字段级 diff（≠/= 高亮），产物二进制 diff 为成熟化方向 |
| H1 | 环境中心 | dev/test/prod 三态卡片 + 详情；prod 冻结 22:00-08:00 + 双人审批（与 .ai/env 纪律一致） |
| H2 | 部署拓扑图 | 应用→渠道连线（内建 SVG 直角连线；桌面依赖 Web 产物为核心边） |
| S1 | 事故与事件流 | 失败单自动转事故单（P1-P3、MTTR、回滚就绪），处置链路接 A5/C1/C3 |
| S2 | 灰度发布管理 | 5%→50%→100% 放量 + 成功率 + 暂停/恢复 |
| G1 | 集成中心 | 代码源/制品库/监控/通知渠道连接卡；凭证脱敏，异常连接会阻塞 S1/D2 |
| X1 | 全局搜索中心 | 发布单/应用/成员聚合搜索（F2 命令面板的数据面），分组结果可跳转 U2/A3/E1 |

数据层：`packages/core/src/prototype/ops.ts`（9 项纯函数 + 9 项单测），续用确定性种子。

## 关键口径

- **R1 与 A1/H1 联动**：就绪度审批项复用 approvalFlow 签核数，prod 窗口判定复用 H1 冻结策略——三页同一口径，不各写一套。
- **S1 与 S2 分工**：S1 是「失败后」的事故处置，S2 是「发布中」的放量控制；灰度异常的出口指向 A5 回滚。
- **X1 与 F2 分工**：同一 `globalSearch` 数据函数；F2 是键盘唤起的命令面板，X1 是完整结果页。

## 被否的选项

- **引入图表库渲染拓扑/雷达**：延续零依赖纪律（见 03 号 ADR）。
- **事故单独立建模（脱离失败发布单）**：当前产品口径「失败即事故」，独立工单体系超出演示台范围，列为成熟化方向。
- **假登录/认证原型**：同 04 号 ADR，身份仅演示切换。

## 验证

三端 typecheck、212 项单测、web build 全绿；Web 10 新路由浏览器逐页走查 + 就绪度页截图核对。过程中修复：ops 误引 visual 的 ENV_VARS（改从 data 导入）、未用 dayKey（一次 shell 脚本误删 165 行，已从 git 恢复并以精确编辑重修——教训：文件修改一律走结构化编辑工具）。
