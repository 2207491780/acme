# 原型增量六：内容与治理域（W1-W4）+ 表格进阶/新手引导（X2/X3）

日期：2026-11-12
关联：`2026-11-12-02`（落点）、`2026-11-12-06`（通用件闭环）

## 背景

通用组件清单闭环后，对剩余管理端缺口做最后一轮补全：内容管理、功能开关、组织架构、数据备份，以及横向的表格深度能力与上手引导。

## 决定

新增 6 项（registry 新域「内容与治理域」+ 横向 X2/X3）：

| ID | 名称 | 核心口径 |
|---|---|---|
| W1 | 公告与规范中心 | 公告置顶优先 + **Markdown 编辑原型**（纯文本渲染，分屏预览需登记依赖）+ 规范/指南/复盘文档索引 |
| W2 | 功能开关管理 | 运行时开关：影响面/责任人/作用域标注；变更「未保存」提示 + 保存留痕（审计口径）；prod 双人审批开关标「不建议关闭」 |
| W3 | 组织架构管理 | 部门树增删与归属（叶/分组标签）；**删除节点走 Popconfirm 二次确认**（F7 规格） |
| W4 | 备份与迁移中心 | 快照清单（演示）+ **导出当前数据（真实下载）** + 导入预览 diff + Popconfirm 确认 → **真实 IMPORT 写入 store**（首个写正式 store 的原型，与 Settings 同口径） |
| X2 | 表格进阶模式 | 展开行 / 列显示自定义 / 密度切换 / 固定列；万行级虚拟滚动列为成熟化方向 |
| X3 | 新手引导清单 | 上手六步：三项由真实 store 自动判定（已发布/已审批/有产物），三项手动确认；进度即上手路径（创建→流转→审批→产物→发布→回滚演练） |

数据层：`core/prototype/content.ts`（公告排序 pinned 优先、开关元数据完备性、引导自动判定、快照规模对齐）+ 5 项单测。

## 关键口径

- **W4 的 IMPORT 是真实能力**：Settings 页同款 reducer 动作；非法数据拒收不覆盖（parseState 保证）——原型第一次有「可写正式 store」的合法例外，理由：导入本就是正式功能。
- **W3 删除纪律**：含子节点的分组不可直接删（先清空），根节点禁删。
- **X3 判定混合**：自动项体现「真实数据驱动」优势，手动项承认演练类动作不可检测。

## 被否的选项

- **W1 引入 markdown 渲染库做分屏预览**：未登记依赖；原型按纯文本渲染 + 说明迁移路径。
- **W4 恢复快照直接写 store**：演示快照非真实备份，恢复会误导；真恢复须先导出（卡片已按此提示）。

## 验证

三端 typecheck、221 项单测、web build 全绿；6 新路由浏览器走查 + 截图核对。
