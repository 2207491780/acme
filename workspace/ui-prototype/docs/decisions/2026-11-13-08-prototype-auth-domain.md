# 原型增量七：认证域（L1 登录）——推翻增量四的被否选项

日期：2026-11-13
关联：取代 `2026-11-12-04`（用户域）中被否选项之一；`2026-11-12-02`（落点）

## 背景

增量四登记用户域原型时，明确否决「登录/认证原型」：当时后端认证面尚未成形，原型层做假登录页没有可对齐的契约。此后 platform-auth 服务落地（B 端登录 / 图形验证码 / 防爆破 / C 端双令牌），认证交互的真实形态已可考——登录页是管理端信息架构不可缺的第一屏，无原型则正式实现无视觉基准。据此在 2026-11-13 于本区新增认证域 L1（`web/pages/Login.tsx`、`mobile/LoginScreen.tsx`），并以 `apps/frontend/web/src/pages/LoginPage.tsx` 按此原型与后端契约完成正式实现（成熟化迁移）。

## 决定

1. 新增「认证域」L1 登录原型：租户 + 账号 + 密码 + 图形验证码的完整表单信息架构，左栏平台能力叙事（多租户隔离 / 网关验签 / 多端同源）。
2. 正式工程登录页按本原型实现（`LoginPage.tsx` 自述来源）；验证码形态对齐后端 `GET /admin/v1/auth/captcha`（data-URI 图形码）。
3. 生命周期口径（`web/README.md`）：登录域已成熟化迁移，正式实现为准；本区 `login` 条目保留为**已迁移（L1 归档态）**——后续若删除该注册项，须连同本 ADR 与映射表同步更新，避免「正式登录 vs 原型登录」被误读为并存的两套实现。

## 被否的选项

- **维持增量四口径（不做登录原型）**：后端契约已实存，缺原型只会让正式实现凭空造视觉——原否决的前提（无可对齐契约）已消失。
- **原型层接真实后端登录**：原型区保持零后端依赖（演示数据确定性）；真实联调属正式工程职责，迁移后已达成。

## 影响

- 审阅口径修正：`2026-11-12-04` 的被否选项以本 ADR 为准；「无假登录页」约束终止。
- 本 ADR 与 `web/registry.tsx` 的 `login` 条目、`LoginPage.tsx` 头注释三方互证。
