# 原型增量三：用户域（U1-U3）

日期：2026-11-12
关联：`2026-11-12-02-prototype-zone.md`（落点约定）、`2026-11-12-03-prototype-visualization.md`（增量纪律延续）

## 背景

用户要求补齐「用户、用户详情」等以成员为主体的原型。现有 D1（成员与角色）是管理员视角的权限配置卡，缺「以人为主体的工作负荷视图」与「个人档案页」。

## 决定

新增 3 项（registry 域「用户域」）：

| ID | 名称 | 内容 |
|---|---|---|
| U1 | 用户列表 | 带工作负荷的成员目录：搜索/角色过滤/排序，负责人发布单数、审批待办、最近活动；点击行进详情 |
| U2 | 用户详情 | 个人档案：头像/角色/应用、负责发布单（联动 A3）、审批待办与签署记录（A1 口径）、操作留痕（C3 口径）；`?user=` 参数直入 |
| U3 | 我的工作台 | 「当前身份」聚合：待我审批（本地通过/驳回）、我负责的进行中、我的动态；身份可切换走查不同角色 |

数据层：`packages/core/src/prototype/user.ts` —— `memberDirectory`（全成员负荷）/ `memberProfile`（档案，不在册返回 null）/ `collectApprovals`（审批记录收集），5 项单测锁定一致性（目录覆盖全成员、所有权划分与 release.owner 对齐、待办/签署分区）。

## 关键口径

- **U1 与 D1 分工**：D1 = 管理员配置权限（角色矩阵），U1 = 带负荷的目录视图；共享 `MEMBERS` 数据源，不重复建模。
- **身份概念**：正式应用无登录态，U3 用「当前身份」切换器演示个人视角；成熟化时接真实登录态。
- **APP 子导航**：U2 详情作为 U1 的内嵌子页（保持 registry 单一入口），Web 端为独立路由 `user-detail`。

## 被否的选项

- **U1 重复实现权限矩阵**：与 D1 职责重叠；U1 只引用角色标签不展示矩阵。
- **引入「登录/认证」原型**：project.md 明确「没有后端鉴权」，身份仅作演示切换，不做假登录页。

## 验证

三端 typecheck、203 项单测全绿；Web 3 新路由浏览器逐页走查 + 用户详情截图核对。
