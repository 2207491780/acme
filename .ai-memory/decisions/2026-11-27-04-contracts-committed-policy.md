# 契约入库政策补记（2026-11-20 起契约 draft 即提交，废弃「只写入不提交」）

日期：2026-11-27（补记 2026-11-20 政策翻转）

## 背景

contracts/ 是契约驱动多代理流程的协调点（REQ-ID 契约实例与 code-review 的 REVIEW-\* 报告）。2026-11-14 建流程时口径为「只写入不提交」：目录内容 git 忽略，仅 README 入库锚定，契约被视为流程现场而非仓库资产。实践一周后暴露两个问题：需求号/迁移号仅靠本机文件系统防撞（并行会话/多机协作取号会撞号）；契约现场不随 git 走（跨会话/跨机无法接管进行中的需求）。2026-11-20 翻转为入库：draft 即提交、confirmed 后状态更新再提交，.gitignore 注释、multi-agent.md 不变式 1、ai-coding-dev leader / team-leader SKILL 同步改口径。当时未写独立 ADR，且漏改 contracts/README.md——README 仍宣称「只写入不提交」，与实际相反，直至 2026-11-27 AI 配置体检 #1 发现（见 `docs/ai-config-review-2026-11-27.md`），本次修正并补记。

## 决定

1. **契约文件入库**（2026-11-20 起生效）：`contracts/<REQ-ID>.md` draft 即提交，confirmed 等状态更新后再次提交；需求 DONE 后原地保留，「流程状态」节是唯一现场，新会话读该节即可接管。
2. **取号防撞以入库记录为准**：需求号/迁移号占用随 git 协调，跨人取号前先 `git fetch`（见 `.ai-memory/playbooks/multi-agent.md`「多人协作集成纪律」），不再依赖同机文件系统。
3. **code-review 蜂群唯一入库产物** `contracts/<REVIEW-ID>.md` 同口径落 contracts/；评审报告不产生 REQ、不写第二份 md（ADR 2026-11-26-02）。
4. **安全红线不变**：契约禁存任何凭证/密钥/个人隐私数据。
5. **并行工作树经 `../../contracts/` 跨树读取**：contracts 在主工作树持有，避免多树同时写。
6. **README 口径修正**（2026-11-27 体检 #1）：`contracts/README.md` 改为本 ADR 口径，废除「只写入不提交」段落。

## 被否的选项

- **维持「只写入不提交」**：否决——取号防撞退回本机文件系统，跨会话/跨机接管失效，与多机并行协作（two-tier-deployment、跨人取号以入库记录为准）的既有实践冲突。
- **仅 confirmed 后提交（draft 留本地）**：否决——draft 阶段正是取号与分工协调窗口，不提交则防撞失效；且「流程状态」节是唯一现场，缺 draft 会使新会话无法接管进行中的需求。
- **契约迁出仓库根改放 .ai-memory/**：否决——contracts/ 已是全部角色卡、命令与手册引用的既定路径，迁移成本大于收益。
