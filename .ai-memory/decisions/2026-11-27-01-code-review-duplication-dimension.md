# code-review 固化「重复声明与冗余逻辑」检查维度（无白名单扫描 + 三类判定）

日期：2026-11-27

## 背景

评审 REVIEW-20261127-010308 第 1 轮漏检了 `@RequirePermission` 自定义注解在 4 个平台的重复声明，第 2 轮靠人工专项扫描 + 重派角色才发现。根因有四条：① 阶段 0 事实清单只有「结构清单」（模块 / Controller 数 / 迁移目录 / API 模块 / 租户网关类），没有「声明清单」，工人按清单外事实不得推导的纪律自然看不到重复声明；② 委派单未把「重复声明 / 冗余逻辑」列为检查维度，工人又被要求不得推导清单外事实；③ 补扫用了 Spring 内建注解白名单，把全部自定义注解过滤掉了；④ 探针报出 `RequirePermissionInterceptor`×4 后被按「bean 名不同 → 非冲突」错误排除，没有核查代码重复本身。教训是：重复声明维度必须进入阶段 0 固定事实源并随每份委派单下发，检测口径必须显式禁止白名单与「按命名冲突排除代码重复」。

## 决定

1. **阶段 0 增加第 6 类固定事实源「重复声明与冗余逻辑」**：自定义注解 `@interface` 声明、跨模块同名类/同名方法体、前端跨端重复类型与 HTTP 客户端、同名 Flyway 迁移（区分独立 location）、重复配置键/常量；每条带 `file:line`，不得用 Spring 内建注解白名单替代全量扫描。`.ai/skills/code-review/SKILL.md` 与 `.ai/agents/code-review/code-review-leader.md` 的阶段 0 清单同步。
2. **验证纪律增加重复检测强制口径**：必须**无白名单**扫描（覆盖自定义注解与自定义类型）；每个候选判为 **真实重复 / 模块特化 / 探针假阳性** 三类之一并写依据；「bean 名不同」「显式限定符不同」只能排除 Spring bean 冲突，**不得据此排除代码重复**；同名类必须比对方法体、注解元信息（如 `@Target`）、异常口径差异后才可结案；探针候选不得由 leader 单方面按命名冲突排除，须回传工人复核，结论进第 7 节轮次记录。
3. **委派链自包含**：leader 每份委派单都随单下发第 6 类清单节与上述强制口径；`.ai/skills/code-review/templates/task-brief-template.md` 输入节增加「重复/冗余维度」占位（含三类判定口径），子 Agent 不读流程文档也能执行；多轮打回仍只在唯一 md 第 7 节追加。
4. **角色职责固化**：`quality-reviewer` 承担重复声明/冗余逻辑专项（自定义注解、同名类、**方法体字节一致**、跨端重复类型），给出三类判定口径与 P0–P3 分级参考——安全/权限相关分叉按 **P2 起**（可致越权/全局失效升 P0/P1），纯重复按 **P3**；`module-inspector-be` 负责跨模块重复声明与行为漂移（注解 / 拦截器 / 网关 / TypeHandler / Job / 配置属性），`module-inspector-fe` 负责跨端重复声明与行为漂移（core/mobile/web 类型、HTTP 客户端、i18n 资源、mock 数据）。双端仍互禁读对端实现。
5. **回归防漂移**：`.ai/tests/swarm-docs.test.mjs` 增加断言，覆盖 SKILL 阶段 0、leader 委派、quality-reviewer 口径、模板占位与双端职责；改完统一 `node .ai/sync.mjs` 派生、`--check` 校验并跑 `.ai/tests/` 全量测试。

## 被否的选项

- **一次性写个白名单探针排查 `@interface` 就结束**：否决——白名单正是本次漏检根因，且与「自定义注解须纳入扫描」相冲突；改成无白名单扫描并写入验证纪律才能防复发。
- **仅在评审报告第 6 节/第 7 节补记这次漏检**：否决——只补记录不改阶段 0 清单与委派单，下一轮工人仍看不到该维度，会再次靠用户提醒才发现。
- **把该维度塞进既有「工程质量」职责、不随委派单下发**：否决——子 Agent 不读流程文档，只在角色描述里笼统提「重复」无法形成带 `file:line` 的声明清单与三类判定；必须由 leader 在每份委派单中下发第 6 类清单与判定口径。
- **保留「bean 名不同 / 显式限定符不同 → 非冲突」作为候选排除依据**：否决——该依据只适用于 Spring bean 冲突，不能证明代码不重复；本次 `RequirePermissionInterceptor`×4 即因此被错误结案，须改为比对方法体与注解元信息后按三类判定。
