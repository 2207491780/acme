# code-review 蜂群能力升级（清单四层化、角色映射、报告机器校验、L1 门禁接线）

日期：2026-11-27

## 背景

上一轮固化「重复声明与冗余逻辑」后，用户给出完整评审清单，要求把清单升格为蜂群一等能力，最高优先级为架构/设计/依赖/模块职责。探索确认现状缺口：只有文档静态断言，没有评审能力演练；报告没有机器校验；L1 未接满现有零依赖门禁；`contract-preflight.md:14` 仍写「五类清单」，与阶段 0 六类事实源漂移。ESLint / axe 不在锁文件，按红线和现有工具口径不得新增依赖。此前 L2 两名工人对整个共享目录执行清理导致其他角色探针被提前删除，也暴露了 `--cleanup` 缺作用域白名单。

## 决定

1. **清单唯一源**：新增 `.ai/skills/code-review/review-checklist.md`，把用户清单合并去重为四层——Tier0 最高（架构与 DDD 分层、单一职责/上帝类/大函数、开闭与硬编码分支、依赖方向与循环依赖、跨层跨模块私有能力、依赖引入、第三方选型、配置分离、复用复制粘贴、扩展点、技术债、DTO/BO/DO/VO 边界、模块职责）；Tier1 业务与正确性（需求匹配、分支全覆盖、状态机、幂等、业务约束、边界值、补偿回滚告警、分布式事务、权限、逆向残留、时区/金额/并发、入参校验与字段脱敏等）；Tier2 安全/性能/并发/数据库/异常日志/接口 RPC MQ/部署/合规审计兜底；Tier3 交 CI/L1（编码规范、Sonar 规则、a11y、覆盖率、文档格式）。每条写检查要点、证据形态（`file:line` 或命令输出）、负责角色、是否交 CI/L1；用户 6 类概要已并入四层。
2. **优先级与一票否决**：Tier0 最高；安全与架构重大缺陷一票否决；Tier3 由 L1/CI 或现有工具处理，蜂群只抽样复核并标「交 L1」，**不得把 typecheck 或测试通过表述为 lint 通过**，禁止为过检查新增依赖（ESLint/axe 不在锁文件）。
3. **角色映射，不新增角色/命令、不改 engine**：CP 负责接口契约/版本兼容/DTO-VO 边界/返回字段脱敏/API 文档并把「五类」改为「六类」；BE 负责 Tier0 全部 + Tier1/Tier2 后端部分；FE 负责前端组件/状态/表单/防抖/路由权限/兼容/资源/内存泄漏/打包 + 前端 XSS/a11y 人工复核（禁读后端不变）；FS 负责状态机/补偿/幂等/消息顺序/调用链异常；CV 负责三向一致/DTO-BO-DO-VO 不混用/错误码/版本兼容/字段脱敏；IO 负责依赖引入/版本冲突/废弃漏洞/环境隔离/灰度回滚/容量/SLA/降级；QR 负责技术债/复杂度/复用重复/方法长度/扩展点，风格类只抽样标「交 L1」；VA 按 Tier 分级与一票否决裁决，历史债隔离不变。所有角色保持 manual 文案、回传、脚本边界、tools 不变；leader 每份委派单下发按角色节选的维度与优先级。
4. **模板与报告**：委派单模板增加「维度节选 + 优先级 + 交给 CI/L1 项」占位；报告模板在第 2 节增加可选「维度覆盖矩阵」行，七节结构不变。
5. **工程化脚本（零新增依赖、遵守跨平台六条）**：新增 `validate-report.mjs`，只读校验七节、P0–P3、每条意见的 `origin:`/证据/建议/归属/文件:行、第 6 节 L1/L2 与失败项 `SKIP(`、第 7 节轮次，输出 PASS/FAIL 与缺失项，退出码 0/1；`run.mjs` 增加子命令前的 `--timeout <ms>`，超时输出结构化 `SKIP(超时 …)` 而非裸 SIGTERM，`--cleanup` 增加白名单（目标须在 `.ai-tmp/code-review/` 之下且不得是共享根本身，越权非零退出），保留 `execFile(...{shell:false})`、`--mvn`、`--cleanup` 既有行为；新增 `l1-checks.mjs`，从 PATH 扫描 `node_modules/pnpm/bin/pnpm.cjs`，经 `execFile(process.execPath, [pnpmCli, ...])` 支持 desktop-check / theme-tests / test-shard <包名> / build，登记为「已有检查」，不造 lint。
6. **L2 目录边界**：探针改为 `.ai-tmp/code-review/<REVIEW-ID>/<role>/probe*.mjs`，工人只清理本人子目录，leader 收尾统一清理，白名单防共享目录误删。
7. **验收**：`.ai/tests/swarm-docs.test.mjs` 追加清单四层/角色映射/manual 不回退/五类修正/L2 子目录断言；新增 `code-review-checklist.test.mjs`、`review-validator.test.mjs`（`.ai-tmp/` fixture + `fs.rm` 清理）；扩展 `code-review-scripts.test.mjs` 的 timeout 结构化 SKIP、cleanup 白名单、l1-checks 静态与行为断言；统一 `node .ai/sync.mjs`、`--check`、`node --test ".ai/tests/*.test.mjs"`，并用真实历史报告跑一次校验器。

## 被否的选项

- **把用户清单塞进既有「工程质量」角色描述、不建独立清单源**：否决——清单条目与证据形态、角色归属、CI/L1 去向需要结构化单一源，散在角色描述里会再次漂移（`五类清单` 即为先例）。
- **新增 lint/a11y 依赖或用 shell 拼命令接门禁**：否决——ESLint/axe 不在锁文件，红线禁止新增依赖；shell 拼接与平台分支违反跨平台六条，改用 PATH 扫描 pnpm.cjs + `execFile`。
- **仅在报告末尾人工补写维度覆盖说明**：否决——无法机器校验，且不可防止漏检；改为模板可选行 + `validate-report.mjs` 结构门禁。
- **保留无边界的 `--cleanup` 与共享 L2 目录**：否决——已发生共享目录被误删；改为每工人子目录 + 白名单，防止越权清理。
- **新增评审角色或命令入口（`/review`）**：否决——manual 档定义为仅显式对话触发，新增角色/命令会制造隐式入口并破坏既有 tools 与信息隔离口径。
