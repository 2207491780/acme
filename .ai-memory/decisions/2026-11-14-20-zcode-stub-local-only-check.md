# .zcode 派生存根标记 localOnly：--check 缺失不判错，存在必须一致

日期：2026-11-14
背景关联：`2026-11-14-19-multi-agent-contract-workflow.md` 决定 7（ZCode 引用存根经 `.ai/tools/zcode/` 派生到 `.zcode/`）。

## 背景

19 号决策落地后首次推送，CI 四个 run（两分支的 ci / ai-rules-sync）全红：`sync --check` 报「缺失 .zcode/agents/*.md」共 6 处。根因：`.zcode/` 整体 git 忽略（ZCode 自管理约定），派生的存根不随提交分发——**全新检出（CI/协作者）必然缺失**，而 `--check` 把这些文件与入库派生物同等对待，判为不同步。本机全绿是「恰好在本机派生过」的假象，未在全新克隆中复现是验证缺口。

## 决定

1. `TOOLS` 条目新增 `localOnly` 标志（当前仅 zcode）：语义 = 该目标**不入库、本机派生**。
2. `--check` 对 localOnly 目标：**缺失 → 跳过不判错**（输出 `⏭️ … 跳过校验`，计入 summary）；**存在但与 `.ai/` 不一致 → 仍判错**（防漂移，本机一致性不放松）。
3. `sync`（写模式）对 localOnly 目照常写本机目录；孤儿检测不变（存在带派生标记的残留仍报）。
4. 回归锁定：新增 `should_treat_missing_local_only_target_as_ok_in_check_but_mismatch_as_fail`（缺失跳过 / 重建 / 漂移判错三段断言）。

## 被否的选项

- **提交 `.zcode/` 入库（取消忽略）**：否决——违反「ZCode 自管理」约定，会话态/工作流草稿混入版本库。
- **--check 对缺失的 .zcode 一律静默跳过（无标志，按目标路径硬编码）**：否决——语义应显式声明在派生目标上，硬编码路径不易扩展且无回归区分。
- **ZCode 存根退回手工本地维护（撤销派生）**：否决——回到「重复声明」问题（用户明确要求引用公共源）。
- **只 re-run CI 不改引擎**：否决——红灯根因在引擎语义，重跑必然复红。
