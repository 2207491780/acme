# code-review 动态启用集合（角色池固定 9 个，按范围/风险/维度命中启用）

日期：2026-11-27

## 背景

此前执行卡固定为「四路并行、7 工人全部回报」：无论评审范围是纯文档、单端普通 CRUD，还是认证/租户/全分支高风险，都启用同一套角色。用户指出「智能体的数量和分工应当按照当前的情况进行合理调整，而非一成不变」。固定全员带来两类浪费：小范围评审派了与范围无关的角色（无契约变更却派 CP、无调用边却派 C 路三人），且报告无法说明未参与角色是「不在范围」还是「漏审」；高风险评审反而可能因平均用力而分工错配。需要在不动角色池、不动 tools / manual / 命令入口 / 唯一产物 / 写入口 / 脚本边界 / 只读裁决的前提下，把「本轮启用哪些角色」变成 leader 的显式决策并留痕。

## 决定

1. **角色池固定、启用集合可变**：仍为 9 个固定角色定义（7 工人 + leader + 裁决员）；tools、`engine.code-review: manual`、无命令入口、唯一 md、leader 唯一写入口、工人只在 `.ai-tmp/code-review/<REVIEW-ID>/<worker>/` 写脚本、裁决员纯只读全部不变；不删除角色定义、不新增角色或命令。动态只体现在本轮启用集合（active set），一次评审最多 7 工人 + 1 裁决员。
2. **leader 在阶段 1 选择并登记 active set**：依据评审范围、风险等级、阶段 0 清单命中维度决定，**不默认全开**。选择矩阵写入 SKILL：纯文档/样式/生成物 → QR + VA；单端单模块普通 CRUD → CP（仅 API/契约变更时）+ 对应端 BE 或 FE + QR + VA；跨模块契约/API 一致性 → CP + BE + FE（前端命中时）+ CV + VA；认证/租户/事务/MQ 幂等/安全/双端形态 → 全 7 工人 + VA；全分支/高风险 → 全 7 工人 + VA，第二轮可重派**已启用角色**专项补证，仍只追加同一 md 第 7 节。
3. **分工按维度命中裁剪四路**：A 路 CP 仅契约/API 变更时启用；B 路按命中端选 BE / FE（双端命中才都启用，互禁读对端不变）；C 路仅当清单内有对应调用边/契约/部署/影响面时启用 FS / CV / IO；D 路 QR 始终启用。委派只发给已启用角色；阶段 2 表述改为「四路为可用路由，按启用集合裁剪；同一轮并行委派所有已启用角色」。
4. **留痕与门禁**：报告第 2 节必填「本轮启用角色：…；未启用：…（原因：无相关调用边 / 无契约变更 / 不在范围）」，空缺不算漏审，基线缺口照写；`validate-report.mjs` 校验该登记行，缺失 FAIL；委派单模板增加启用集合/本角色命中维度/未启用角色及原因占位，报告模板增加必填行，保证子 Agent 自包含。
5. **裁决与多轮**：裁决员只裁决已启用角色回传的结论；若 leader 未提供 active set，就地停止上报要求补证，不得猜测。多轮打回可调整 active set（重派已启用角色或启用清单内命中的其他池内角色），调整与原因只追加同一 md 第 7 节，不新建 md。
6. **验收**：`.ai/tests/swarm-docs.test.mjs` 新增选择矩阵、leader 登记、模板占位与不变量断言；`.ai/tests/review-validator.test.mjs` 用 `.ai-tmp/` fixture 验证有启用行 PASS、无启用行 FAIL；统一 sync / `--check` / `.ai/tests/` 全量回归，并用历史报告实测校验器（缺登记行如实报 FAIL，不改报告）。

## 被否的选项

- **删除不常用角色定义、只保留常用角色**：否决——角色池是跨工具固定公共池（9 个定义与 tools/manual 口径已被既有回归锁定），删除会造成派生漂移和命令/权限口径不一致；动态只发生在启用集合。
- **每次评审都全开 7 工人**：否决——正是本次要改的浪费与错配来源，小范围评审派无关角色且报告无法解释空缺。
- **临时新增角色或口头分工、不改 `.ai/` 配置**：否决——子 Agent 只认角色文档与委派单，临时角色不在池内会破坏信息隔离、脚本边界与可追溯性。
- **让工人自行决定是否参与**：否决——启用决策依赖阶段 0 事实清单与范围/风险全局信息，只有 leader 掌握；工人自选会造成重复、漏审与无法登记未启用原因。
