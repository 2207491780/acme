# 前端质量与观测性——E2E 测试（Playwright）+ 错误采集上报

## 背景

- 前端无 E2E（Playwright/Cypress 零命中）、无覆盖率配置；无错误上报/埋点，线上问题不可观测。
- 错误采集端点走公开上报面（未登录亦可报，如登录页白屏），必须挂服务内 `@RateLimit` 纵深限流（与 REQ-20261114-120107 基线一致）；存储落 platform-infra（通用能力域）。
- E2E 主流程以 web 为准（登录/用户 CRUD/字典），mobile E2E 延后；本地运行用真实网关+PG dev 环境（对齐既有本地调试环境指针）。

- [2026-11-14] ② 错误采集范围（TL 提案，待确认）：window.onerror + unhandledrejection + ErrorBoundary 捕获（若 REQ-20261114-120103 已合流则联动）；批量上报（队列+去重+采样）；含 release 版本/路由/traceId 上下文。

## API

> 统一响应体 `Result`；业务失败=`Result.code≠0`（HTTP 200）。

### 错误上报（platform-infra）
- `POST /app/v1/infra/fe-errors`：免鉴权批量上报（数组 ≤20 条/批；字段：type/source/message/stack 截断/route/release/userAgent/occurredAt）；限流超额=`FE_ERROR_RATE_LIMITED`；校验失败整批拒绝不落库。

### 错误查询（platform-infra，权限 `infra:feerror:list`）
- `GET /admin/v1/infra/fe-errors`：分页（type/route/release/时间区间筛选）。

## 验收标准（规格核心）

- AC-1 given Playwright 主流程用例（登录/用户 CRUD/字典）when 对 dev 环境执行 then 全绿且可重复（幂等测试数据）→ 用例 `should_走通登录仪表盘用户CRUD字典到登出_when_专用测试账号执行主流程`
- AC-2 given E2E 数据 when 用例结束 then 清理策略生效（专用测试账号，不留脏数据）→ 用例 `should_清理全部前缀残留用户_when_用例结束存在自建数据`
- AC-3 given 前端抛未捕获错误/未处理 Promise rejection when 上报 then 批量到达端点并落库（含 route/release 上下文）→ 用例 `should_批量落库并携带route与release_when_前端上报未捕获错误数组`
- AC-4 given 同一错误指纹重复发生 when 上报 then 客户端去重/采样生效，无风暴 → 用例 `should_同指纹仅入队一次_when_同错误重复发生`
- AC-5 given 超限/非法 payload when 上报 then 限流或整批拒绝，库无脏数据 → 用例 `should_整批拒绝返回FE_ERROR_BATCH_INVALID_when_批量超20条或字段校验失败`
- AC-6 given 白名单截断 when stack 含敏感串 then 上报内容不含密钥/凭证（红线用例）→ 用例 `should_上报内容不含密钥凭证_when_stack含敏感串`
- AC-7 given 权限 when 查询端点 then 仅持 `infra:feerror:list` 可用；无权限统一拒绝 → 用例 `should_统一拒绝code非0_when_无权限查询错误列表`
- AC-8 given 错误管理页 when 查看 then 分页/筛选/详情（脱敏展示）对齐 CRUD 范本 → 用例 `should_渲染分页与筛选_when_打开错误管理页`
- AC-9 given 全部完成 when `mvn test` 与前端三件套（E2E 本地跑通）then 全绿 → 门禁项（无独立用例）
