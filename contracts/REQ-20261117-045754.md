# 对象存储直传与租户配额（可配置）

## 背景
- 已实测事实（TL 探索 2026-11-17）：`ObjectStorage` 仅 5 方法（put/get/remove/exists/url），**无 PUT 预签名**——`url()` 仅按 urlMode 返回 GET 下载预签名（Minio `Method.GET` / OSS generatePresignedUrl）；`ObjectKey.of(namespace,name)` path=namespace/yyyy/MM/dd/name；`FileUseCase.objectKeyOf(path)` 硬校验 5 段；objectKey 现为 `files/yyyy/MM/dd/uuid.ext` **无租户段**（租户隔离仅靠 sys_file.tenant_id 列）；校验链（size→扩展名/MIME 白名单）全在 upload()；`StorageProperties`（acme.storage）含 enabled/type(LOCAL|MINIO|OSS)/endpoint/keys/bucket/presignTtl/urlMode/Local.rootDir/Upload{maxSize=10MB,allowedContentTypes,retentionDays}；enabled=false 时 Properties bean 一并消失（StorageSwitchTest 锁定）；platform-infra 有 Redis 依赖与配置（stream 去重在用）；TenantContext 在 infra 全部 /admin/v1/infra/** 请求可用（InternalTokenAuthFilter 绑定）；`infra:file:*` 4 权限点已存在（V7 种子）；文件集成测试为 PG+Redis Testcontainers（REQ20261114071607FileServiceIntegrationTest 模式），**无 H2 schema.sql**；MinIO 适配器既有 Testcontainers 测试（无 Docker 跳过）。
- 前端：UploadButton=隐藏 input+uploadFormData（multipart POST）；CSP `connect-src 'self'` 仅生产构建注入（vite injectCsp），直传到 minio/oss 域名会被拦——**直传统一走同源**：LOCAL 用服务端票据 PUT 端点；MINIO/OSS 预签名 URL 需部署侧同源反代（endpoint 配公网同源地址＋nginx 保留 Host 转发，env-stack 文档交付，本 REQ 不部署不实测）。
- env-stack：k8s/base 现有 9 清单＋kustomization（images 占位 5 服务）；deploy.sh rollout 等待清单硬编码（sts: postgres/redis/nacos；dep: 5）；prod overlay 注释明示存储选型延后。
- **本 REQ 无 Flyway 迁移**（sys_file 现列够用；objectKey 引入租户段为格式演进，objectKeyOf 兼容 5/6 段）。

## 确认记录（契约的权威解释；只存结论条目，禁存对话原文）
- [2026-11-17] ① 直传统一口径：`POST direct-upload-preparations` 校验（空文件/大小/白名单/配额/图片语义）→ 生成**带租户段** objectKey（`files/{tenantCode}/yyyy/MM/dd/uuid.ext`）→ LOCAL 返回服务端一次性票据 PUT 端点（Redis ticket TTL 5min，绑定 objectKey+meta+租户+操作者）；MINIO/OSS 返回 facade 新方法 `presignUpload` 的预签名 PUT URL（Content-Type 头随签名）。客户端 PUT 原始字节（带 Authorization？——LOCAL 票据端点走既有认证面（authed），MINIO/OSS 预签名 URL 不带认证头）→ `POST direct-upload-completions` 校验对象存在＋大小一致 → 落 sys_file（幂等：同 objectKey 未删行直接返回既有 FileView）。multipart POST "" 端点保留不动（兼容），内部同样走租户前缀新格式。
- [2026-11-17] ② 租户命名空间：objectKey 统一 `files/{tenantCode}/yyyy/MM/dd/name`；`objectKeyOf` 兼容 5 段（存量行）与 6 段（新格式）；服务端组装租户段（来自 TenantContext），客户端不可传。
- [2026-11-17] ③ 租户配额：`acme.storage.quota.default-bytes`（Long，0=不限，默认 1073741824=1GiB）；口径=该租户 sys_file 未删行 size 总和＋本次大小 ≤ 配额；preparations 与 multipart upload 同检；超限新错误码 STORAGE_QUOTA_EXCEEDED（413 语义）。注：并发上传下配额为近似护栏（SUM 非锁），文档注明。
- [2026-11-17] ④ 图片语义：contentType 以 image/ 开头时，服务端用 ImageIO 校验「可解码＋宽高 ≤ acme.storage.upload.max-image-px（默认 4096）」；不可解码/超尺寸 → STORAGE_IMAGE_INVALID（400 语义）；multipart 与 direct-completion 两条路都执行（completion 侧对下载的流执行）。
- [2026-11-17] ⑤ 环境可配置性：类型切换经既有 spring 配置（Nacos data-id 同机制）即可，代码零改动即满足「可配置」；文档化 `acme.storage.*` 全键（BACKEND 或 ENV-STACK 附录小节）＋env-stack 交付 minio.yaml（StatefulSet+SVC+PVC，标注未部署）＋deploy.sh rollout 清单扩展＋prod overlay 注释更新为「minio 就绪可启用」＋nginx 同源反代样例（注释形态，ENV-STACK 内）。
- [2026-11-17] ⑥ 幂等与安全：completion 以 objectKey 查未删行命中即直接返回（不重复落库）；ticket 单次消费（Redis getdel 语义，Lua 或 WATCH 侧——实现者按现有 RedisDedupStore 风格选最小实现）；ticket 绑定租户与操作者防跨租户替传；completion 校验 storage.exists＋size 与 preparation 一致（容差 0）。

## API
### 直传准备（POST /admin/v1/infra/files/direct-upload-preparations）
- 权限 `infra:file:upload`；入参 `{fileName, contentType, size, bizType?, bizId?}`；校验链=空/大小/白名单/配额/图片（image 语义在 completion 校验真实字节，preparation 仅白名单与大小/配额）。
- 返回 `Result<DirectUploadPreparationView>`：`record DirectUploadPreparationView(String objectKey, String uploadUrl, String method, Map<String,String> headers, long expiresInSeconds, String ticket(仅 LOCAL 模式返回，MINIO/OSS 为 null))`。
### 直传完成（POST /admin/v1/infra/files/direct-upload-completions）
- 权限 `infra:file:upload`；入参 `{objectKey, fileName, contentType, size, bizType?, bizId?}`；校验=objectKey 归属当前租户（6 段租户段比对，不匹配 FORBIDDEN 语义）＋exists＋size 一致＋图片语义；落库返回既有 `FileView`。
- 失败码：STORAGE_OBJECT_MISSING（404 语义）/ SIZE_MISMATCH（400）/ QUOTA_EXCEEDED（413）/ IMAGE_INVALID（400）/ TICKET_INVALID（400，LOCAL 票据失效/已消费/租户不符）。
### 票据直传（PUT /admin/v1/infra/files/direct-uploads/{ticket}）
- 认证端点（既有认证面）；原始字节体（非 multipart）；Content-Type 头须与 preparation 一致；写入对象（Local put）；成功 200 空 Result。**MINIO/OSS 模式无此端点路径**（客户端直 PUT 预签名 URL）。
