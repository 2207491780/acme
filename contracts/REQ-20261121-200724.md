# framework-job 升级执行器 SDK + 存量任务迁移（JOB-2）

## 背景（钉死事实，均已实测 2026-11-21 主树）
- framework-job：auto-configuration 单行 imports（JobAutoConfiguration，@ConditionalOnAcmeModule("job")+@ConditionalOnClass(LockProvider)）；`@AcmeTask(taskId,mutex,lockAtMostFor,lockAtLeastFor)` METHOD 级；TaskRegistry（重复注册抛 IllegalStateException）；收集器=ContextRefreshedEvent 反射扫描（非 BeanPostProcessor）；JobProperties 前缀 acme.job（enabled/lockAtMostFor PT30M/lockAtLeastFor PT1M/shedlock.mode AUTO）；TaskExecutionAspect 编程式互斥（服务侧不用 @SchedulerLock 注解）。
- @AcmeTask 使用点：仅 platform-infra 4 个保留期清理任务（file/login-log/op-exception/audit retention-cleanup，目录 platform-infra-service/.../internal/job/），模式=@Scheduled(cron="${acme.*.retention-cron}")+taskTrigger.trigger(JOB_KEY,TRIGGER_SCHEDULED) 同径触发+方法 execute(String triggerType) 返回执行记录 id；sys_job_execution 由服务侧 JobExecutionRecorder 写（非框架）。
- JOB-1 执行面对接契约（platform-scheduler-api，源码标注「JOB-2 执行器 SDK 对接契约，字段名/路径不得变更」）：JobDispatchCommand(jobKey,handler,param,ShardContext,fireTime,traceId,attempt)；下发=POST `/internal/v1/job/executions/{executionId}/run`（寻址 lb://{app_name}，X-Acme-Token 内部令牌 sub=platform-scheduler，接单 200+accepted=true→RUNNING）；结果上报=POST `/internal/v1/scheduler/executions/{executionId}/result`（状态 CAS）；执行器注册=POST `/internal/v1/scheduler/executors`（ExecutorRegisterRequest(appName,instanceId,host,port,handlers)）；心跳=POST `/internal/v1/scheduler/executors/heartbeat`（ExecutorHeartbeatRequest(appName,instanceId,handlers)，stale 30s→OFFLINE）；下发通道=纯 HTTP 直推（无 Kafka）。
- 调度中心数据模型：sch_executor_registry(app_name/instance_id/host/port/handlers jsonb/heartbeat_at/status，uk(app_name,instance_id))；sch_job_definition 含 app_name；**OneShotJobRegisteredView/SchedulerJobClient 现主树不存在**（属 BPM-1 未合流产出，JOB-2 禁依赖）。
- bootstrap 单体：聚合四服务；无 Nacos/无执行器注册时调度中心零下发行为（MonolithApplication 注释钉死）；application-monolith.yml 聚合各任务 cron 键。
- infra 旧面：/admin/v1/infra/jobs（JobController list/run/executions，权限 infra:job:list/run）；JobUseCase.list 直接消费 TaskRegistry；sys_job_execution 表+索引既有。

## 确认记录（契约的权威解释；只存结论条目）
- [2026-11-21] ① 用户批量授权（同 REQ-010725 ①）；范围=规划 JOB-2（管理页切 API 归 JOB-3）。
- [2026-11-21] ② 指令通道钉死 HTTP 直推单通道（JOB-1 契约面已锁定；Kafka 兜底候选归 BPM-6/JOB-5 再评估，本期不做）。
- [2026-11-21] ③ SDK 新注解 `@JobHandler`（属性 jobKey/timeoutMs/shardable/描述）：标记「可被调度中心调度的任务」——注册进 TaskRegistry 兼容视图（JobUseCase.list 零破坏）+执行器注册表 handlers 清单+接收下发指令；`@AcmeTask` 标记 @Deprecated 保留本地语义（本地 @Scheduled+TaskTrigger 照跑，不进 handlers、不接单）；两注解共存过渡，删除归后续清理 REQ。
- [2026-11-21] ④ 执行器生命周期：SDK 经 Spring Cloud LoadBalancer `lb://platform-scheduler` 调注册/心跳端点（实例身份 appName=Nacos 服务名+instanceId=UUID+host/port 自报）；心跳周期 ≤ stale 阈值一半（默认 10s，可配 acme.job.executor.heartbeat-interval-ms）；discovery 不可用/调用失败→静默降级（不注册不接单，本地 @Scheduled 兜底继续），恢复后重注册；总开关 `acme.job.executor.enabled`（默认 true；bootstrap 单体 application-monolith.yml 显式 false=纯本地模式）。
- [2026-11-21] ⑤ 指令接收：SDK 各服务自动装配内部端点 POST `/internal/v1/job/executions/{executionId}/run`（路径/字段按 JOB-1 契约面，X-Acme-Token 校验对齐现有 internal 面）；接单后按 jobKey 定位 @JobHandler 方法（缺 handler→accepted=false DISPATCH_REJECTED），同步执行+结果上报（SUCCESS|FAILED+error+耗时），attempt/shard 上下文透传；执行超时 timeoutMs 取 dispatch 参数（超时=FAILED/TIMEOUT 上报，方法线程中断尽力）。
- [2026-11-21] ⑥ 执行历史双轨兼容：@JobHandler 被调度中心下发执行→SDK 上报 result 落 sch_job_execution（scheduler 内核写，JOB-1 已有）；本地 TaskTrigger 手动/兜底触发→仍走 JobExecutionRecorder 落 sys_job_execution（双写期，/admin/v1/infra/jobs 执行历史不断供）；JOB-3 切读中心后归档决策。
- [2026-11-21] ⑦ 存量 4 任务迁移：4 个保留期清理任务改标 @JobHandler（jobKey 沿用现 taskId 值），任务定义种子入调度中心（scheduler V2 迁移：sch_job_definition 4 行幂等种子，cron 取自现 acme.*.retention-cron 默认值、appName=platform-infra、handler=对应 jobKey）；本地 @Scheduled 兜底行保留（executor.enabled=false 或降级时生效；双跑幂等由任务本体保留期语义+互斥锁保证）；triggerType 语义保留（SCHEDULER_DISPATCH|TRIGGER_SCHEDULED|TRIGGER_MANUAL 归一）。
- [2026-11-21] ⑧ 权限点/旧 API：本期零新增权限点、/admin/v1/infra/jobs 面不动（JOB-3 切换）；migrations 仅 platform-scheduler V2。
- [2026-11-21] ⑨ OneShotJobRegisteredView/SchedulerJobClient 为 BPM-1 未合流产出，JOB-2 SDK 面只对接 JOB-1 五端点，禁止依赖上述两符号。
- [2026-11-21] ⑩ 测试口径：Testcontainers PG 集成（注册/心跳/接单/上报/降级矩阵）+内嵌桩 scheduler 端点（JDK HttpServer 照 JOB-1/BPM-1 先例）；@AcmeTask 兼容语义回归（infra 既有任务测试零回归）；种子迁移幂等用例；无前端变更。

## 验收标准（AC 骨架；用例映射已回填）
- AC-1 given: executor.enabled=true+discovery 可用 when: 服务启动 then: 注册成功（appName/instanceId/host/port/handlers）且心跳按周期续期；心跳中断超 stale then: 调度中心侧 OFFLINE → ExecutorSdkIntegrationTest#should_register_with_full_identity_and_heartbeat_periodically_when_executor_enabled ＋ SchedulerV2IntegrationTest#should_mark_executor_offline_when_heartbeat_stale_beyond_30s
- AC-2 given: @JobHandler 任务 when: 调度中心下发 run then: 接单 200+accepted=true→执行→result 上报 CAS 成功（SUCCESS/FAILED/error/耗时全量）；未知 jobKey then: accepted=false DISPATCH_REJECTED → #should_accept_dispatch_execute_and_report_success_when_job_key_registered＋#should_report_failed_with_error_when_handler_throws＋#should_reject_dispatch_without_result_report_when_job_key_unknown
- AC-3 given: 下发含 attempt/shard 上下文 when: 执行 then: 透传至方法（shardable 任务分片参数可见）；timeoutMs 超时 then: 上报 TIMEOUT 且线程中断尽力 → #should_pass_attempt_and_shard_context_to_handler_when_dispatch_carries_them＋#should_report_timeout_and_interrupt_handler_thread_when_execution_exceeds_timeout_ms
- AC-4 given: discovery 不可用/注册调用失败 when: 启动+运行 then: 静默降级不注册不接单，本地 @Scheduled 兜底照跑，恢复后重注册 → #should_degrade_silently_and_reregister_when_scheduler_register_fails_then_recovers
- AC-5 given: executor.enabled=false（单体）when: 启动 then: 零注册零接单，本地调度全量照跑（bootstrap 冒烟口径） → ExecutorDisabledIsolationTest#should_never_contact_scheduler_and_still_run_local_schedule_when_executor_disabled＋MonolithExecutorDisabledSmokeTest#should_disable_executor_for_pure_local_mode_when_monolith_profile_active
- AC-6 given: @AcmeTask 旧任务 when: 本地 trigger then: 语义不变（TaskRegistry/TaskTrigger/sys_job_execution 记录），不进 handlers 不接单 → AcmeTaskLegacySemanticsTest×3＋handlers 排除腿并入 SDK IT 用例1＋JobMigrationZeroBreakTest#should_record_dual_write_execution_and_execute_task_when_trigger_migrated_job_manually
- AC-7 given: V2 种子 when: 迁移+重放 then: sch_job_definition 4 行幂等（重放不重复不覆盖运行态） → SchedulerV2IntegrationTest#should_seed_four_infra_job_definitions_idempotently_when_v2_migration_replayed
- AC-8 given: 4 任务迁移后 when: /admin/v1/infra/jobs 列表+手动触发+执行历史 then: 零破坏（TaskRegistry 兼容视图+双写历史） → #should_list_all_four_migrated_jobs_with_descriptors_when_query_job_registry＋#should_page_execution_history_when_migrated_job_ran_twice
