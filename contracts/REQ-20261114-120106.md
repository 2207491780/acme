# 网关增强——聚合 API 文档 / XSS 清洗过滤器 / 灰度用户选择器

## 背景

- springdoc 仅服务侧聚合（Q-008 既定边界）；网关 webflux UI 依赖在 parent BOM 但未引入，无聚合 UI。
- 网关过滤器链 7 个（Auth/InjectIdentity/Revocation/RateLimit/StripSpoofedHeaders/RequestLog/Trace），无 XSS 清洗。
- 灰度仅配置壳：`GatewayProperties.Gray` + `X-Acme-Gray` 标记头 + SCG 原生路由谓词，无活动路由、无用户选择器。
- CORS origin 白名单经 `ACME_CORS_ALLOWED_ORIGINS` 注入（不动）。

## 确认记录（契约的权威解释；只存结论条目，禁存对话原文）

- [2026-11-14] ① 聚合文档（TL 提案，待确认）：网关引入 springdoc webflux UI（依赖已在 BOM），路由 `/v3/api-docs/{service}` 转发各服务 openapi；`GET /docs` 聚合 UI 按服务分组；`acme.doc.enabled` 可整体关闭（对齐既有单一配置源风格）。
- [2026-11-14] ② XSS 清洗（TL 提案，待确认）：网关过滤器对 query/form 字段做 HTML 实体转义清洗，JSON body 默认不转义（避免破坏富文本类业务），以「可配置豁免路径 + 字段黑名单转义」策略落地；具体策略实施时与 REQ-B 富文本存储形态核对。
- [2026-11-14] ③ 灰度用户选择器（TL 提案，待确认）：选择器规则（用户白名单/比例）落网关配置（Nacos 动态刷新），命中用户请求注入 `X-Acme-Gray: on`，由既有 SCG 路由谓词消费；本轮不做控制台界面。
- [2026-11-15] ④ 裁决（TL，收交付后）：「路由不暴露」采守卫方案——doc 路由仍注册于 SCG，`DocGuardFilter`（order 50）在关闭时前置 404+`DOC_DISABLED`，请求不触达下游，对外等效不可达；程序化路由方案（404 退化为通用 SYS-00-0002）不采。
- [2026-11-15] ⑤ 裁决（TL，backend 升级上报）：网关无 Nacos 配置中心接入且契约「新依赖：无」——灰度规则本轮经 env-stack 文件配置（application.yml/overlay）下发，选择器逐请求实时读 `GatewayProperties`（Spring Cloud 重绑定后生效）；Nacos 动态刷新接入不在本轮范围，留待后续需求。

## API

### 聚合文档（网关，免鉴权 public path 随 acme.doc.enabled 开关）
- `GET /v3/api-docs/{service}`：转发 `lb://platform-{service}` 的 openapi JSON。
- `GET /docs`：springdoc webflux 聚合 UI（服务分组下拉）。
