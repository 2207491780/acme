# SSO/OAuth2 第三方登录一期——授权码客户端 + 账号绑定（B 端先行）

## 背景

- 后端无任何 sso/oauth 客户端；认证体系为自研（jjwt JWS + Redis 撤销集 + LoginGuard），**未引入 Spring Security**——若引 `spring-security-oauth2-client` 需要与既有拦截器安全体系共存，耦合风险高。
- 项目风格克制（自研轻量先例：jjwt、两级缓存、ShedLock 抽象），授权码流程自研可控（state 防 CSRF + code 换 token + userinfo 拉取），仅此一个协议场景。
- 提供商与客户端凭据经环境变量注入（fail-fast，无仓库默认密钥，对齐既有规则）。

## API

> 错误码新增入错误码布局；涉及 302 跳转的端点豁免统一响应体包装（StandardResponseAdvice 既有豁免机制）。

### OAuth2 授权（platform-auth，免鉴权 public path）
- `GET /admin/v1/auth/oauth/{provider}/authorize`：生成 state（一次性、5 分钟 TTL）→ 302 到提供商授权页；未知 provider=`OAUTH_PROVIDER_NOT_FOUND`。
- `GET /admin/v1/auth/oauth/{provider}/callback`：校验 state → code 换 token → 拉取用户标识 → 已绑定=签发本系统令牌并跳转前端；未绑定=`OAUTH_NOT_BOUND`（带一次性 bind ticket 302 到绑定页）；提供商失败=`OAUTH_PROVIDER_ERROR`。

### 账号绑定（platform-auth，登录态）
- `GET /admin/v1/auth/social-bindings`：当前用户绑定列表（provider/绑定时间，不含 open_id 明文）。
- `DELETE /admin/v1/auth/social-bindings/{id}`：解绑（至少保留一种登录方式——若仅密码登录可解绑第三方，反之亦然；`BINDING_LAST` 仅当删后会话方式为零时拒绝）。

## 验收标准（规格核心）

- AC-1 given authorize when 调用 then 302 到提供商授权 URL 且 state 一次性可校验；重复/过期 state then `OAUTH_STATE_INVALID` → 待回填
- AC-2 given 已绑定账号 when callback then 签发系统令牌并 302 回前端会话页 → 待回填
- AC-3 given 未绑定账号 when callback then `OAUTH_NOT_FOUND` 语义路径：带 bind ticket 302 到绑定页，凭 ticket 完成绑定（ticket 一次性、过期拒绝）→ 待回填
- AC-4 given 提供商 token/userinfo 接口失败 when callback then `OAUTH_PROVIDER_ERROR`，无半落库状态 → 待回填
- AC-5 given 解绑 when 删后用户仍有可用登录方式 then 成功；否则 `BINDING_LAST` → 待回填
- AC-6 given 凭据未配置 when 服务启动 then fail-fast（对齐既有环境变量规则）→ 待回填
- AC-7 given 前端 when 登录页展示第三方入口/绑定页流程 then 状态机完整（跳转/绑定/失败提示）→ 待回填
- AC-8 given 全部完成 when `mvn test` 与前端三件套 then 全绿 → 待回填
