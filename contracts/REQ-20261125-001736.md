# 多租户安全收口一期

## 背景（只写实现者不知道的事实；均已在 2026-11-24 调查中实测）

- 全仓 20+ 实体经 MyBatis-Flex `@Column(tenantId=true)` 行级隔离；`TenantContext`（common-context，普通 ThreadLocal 五类上下文之一）+ `TenantBypassScope`（旁路深度计数）+ `CrossTenantAuditLogger`（framework-tenant，结构化日志，**Q-005 决策"不落库"**——本契约修订）。
- 全仓无任何 `@Cacheable`/`CacheManager` 使用；framework-cache 存在但无租户键机制——加租户键属防御性框架能力。
- `DefaultRateLimitKeyBuilder`（framework-core）键形态 B=服务:端别:账号:接口、C=服务:端别:设备:用户:接口、FB=IP 兜底，均无租户维度；`RateLimitKeyInput` 无 tenant 字段。
- 撤销检查 FAIL_OPEN 在两处实现：gateway `RevocationCheckFilter`（order=250）与 bootstrap `BootstrapAuthFilter`（撤销检查段），均"异常放行+WARN"。
- 异步上下文现状全靠手工 bind/clear（ContextSnapshot/ConsumeContexts/命令载荷）；Spring 无全局 TaskDecorator，`@Async`/`@Scheduled` 线程池不自动透传。
- 三层测试口径见 `.ai-memory/playbooks/flex-test-assembly.md`：H2 切片不跑 Flyway；PG 集成 Testcontainers；Maven 完整路径见该手册"构建与运行"。

## API

### 无新增/无变更端点
- 三个公开端点行为与响应形状不变，仅新增访问审计日志（AC-1）。
- 撤销检查失败（fail-closed=true 且 Redis 异常）为框架行为非端点变更：HTTP 503，错误码 `REVOCATION_CHECK_UNAVAILABLE`（段位实现时按 common-contract `ErrorCodeLayout` 既有规则分配，错误码表随代码登记）。

## 验收标准（规格核心）

- AC-1 given 未认证请求 GET /admin/v1/auth/tenants（及 /captcha-policy、/public-config）when 请求进入 then 每请求一条结构化访问日志（logger 约定 `acme.security.public-access`：traceId、clientIp、endpoint、tenantCode（有则记）、UA 摘要），响应语义/状态码/形状零变化 → 待 tester 回填
- AC-2 given `@IgnoreTenant` 旁路激活 when `CrossTenantAuditLogger.record(accessPoint)` then 结构化日志照旧输出，且事件经新增 `CrossTenantAuditSink` SPI 异步投递（operator/tenant/bypass/accessPoint/traceId/时间戳字段自包含，不依赖 ThreadLocal）；未装配任何 sink 时仅日志、不报错（框架可独立运行） → 待 tester 回填
- AC-3 given platform-infra 装配 DB sink when 旁路事件投递 then 落 `sys_cross_tenant_audit`（operator/tenant_id/access_point/trace_id/bypass/created_at，索引 operator+created_at）；异步写失败 → ERROR 告警日志并丢弃该行，主流程零影响；同步日志不受影响 → 待 tester 回填
- AC-4 given Spring Cache `@Cacheable(keyGenerator="tenantKeyGenerator")` 且 TenantContext 绑定 when 同租户两次调用 then 缓存键含 `t:{tenantId}:` 段且二次命中；given 未绑定且旁路未激活 when 调用 then 抛 `TENANT_REQUIRED`（fail-closed）；given 旁路激活 when 调用 then 键含 `t:*:` 段（旁路结果不与单租户缓存混用） → 待 tester 回填
- AC-5 given Spring 应用启用 @Async/@Scheduled when 装配全局 `ContextTaskDecorator`（自动配置） then 子线程五类上下文（USER/TENANT/TRACE/LOCALE/CLIENT）可用且任务结束清理（复用 ContextSnapshot capture/restore）；given 手工线程池 when 用 `ContextExecutors.decorate` 提交 then 等价透传；无上下文场景行为不变 → 待 tester 回填
- AC-6 given TenantContext 绑定 when 构造限流键（B/C 形态）then 键在服务前缀后含租户段；given 未绑定 when 构造 then 键格式与现状完全一致（向后兼容；FB 兜底键不变） → 待 tester 回填
- AC-7 given `acme.security.revocation.fail-closed=true` 且 Redis 撤销检查异常 when 请求经网关/边缘 then 拒绝（503+REVOCATION_CHECK_UNAVAILABLE）；given 默认 false when 同场景 then 行为与现状一致（放行+WARN）；两处实现同开关同语义 → 待 tester 回填
- AC-8 全量回归：既有测试全部通过（`mvn test` 含 PG/Redis IT）；本 REQ 全部新行为有测试覆盖（framework 单测/H2 切片 + infra PG 集成测试覆盖审计表落库链路） → 待 tester 回填
