## 确认记录（契约的权威解释；只存结论条目，禁存对话原文）
- [2026-11-19] ① 语义：web 登录页「扫码登录」生成 ticket 二维码 → **已登录 B 端（员工）身份的 APP** 扫码确认 → web 轮询到 confirmed 后签发**确认者**的 B 端令牌（token=确认者本人，攻击者只能让 web 登录为自己，语义安全）；C 端手机号会话与扫码登录无关；APP 需先有员工账密登录态（新增形态，见②）。
- [2026-11-19] ② APP 员工登录：LoginScreen 增登录方式切换（短信验证码[C 端既有] / 账密[B 端新增]）；B 端登录走 POST /admin/v1/auth/tokens（tenantCode+username+password+captcha——图形验证码按租户策略，APP 渲染 GET /admin/v1/auth/captcha 的 data URI）；**B 端会话独立存储** `acme.auth.bsession.v1`＋独立 BSessionStore（isValidSession 口径：access-only 无 refreshToken，userId wire string）；导航：B 登录成功不进主 Tabs（主 Tabs 仍属 C 端会话），会话暂存并在进入扫码确认页时使用；LoginScreen 双 Tab 形态切换。
- [2026-11-19] ③ ticket 状态机（Redis-only）：`auth:qr:ticket:{id}` JSON{status: created|scanned|confirmed|cancelled|expired, createdAt, createdIp, confirmUserId?, confirmUsername?}，TTL 120s（过期即 Redis TTL 自然失效→查询返回 expired）；创建→created；APP info（B 令牌）→ status 变 scanned（幂等，重复 info 不回退 confirmed）；confirm（B 令牌，Lua GET+DEL 原子单次）→ 校验 B 会话 user 有效 → kickPreviousSessions（B 端互踢语义）→ UserTokenIssuer.issue(userId, tenantId, roles, CHANNEL_B, ACCESS) → SessionRecorder.record＋indexSession＋writeSessionInfo＋LoginLogRecorder.record（channel B，成功）→ status=confirmed（写 confirmUserId/Username 于响应返回前，票即删）；cancel（B 令牌）→ DELETE＋status 记录返回 cancelled；轮询侧（web）GET 只读不改状态。
- [2026-11-19] ④ 端点与豁免：创建 POST /admin/v1/auth/qr-tickets **公开**（body 可空，clientIp 从请求取；IP 频控 Redis INCR+TTL 每分钟 10 次/IP，超限 QR_TICKET_LIMITED 429 语义）；轮询 GET /admin/v1/auth/qr-tickets/{id} **公开**（返回 {status, token?}——confirmed 时 token 字段携 AdminTokenIssued；其他状态 token=null；GET 不消费票）；info/confirm/cancel **认证**（B 令牌；/admin/v1/auth/qr-tickets/{id}/{info|confirm|cancel}）。公开豁免登记三处（auth main/test yml＋网关 auth.b.public-paths＋GatewayRoutingConfigTest 锁定清单）。响应全部 Result 信封。
- [2026-11-19] ⑤ 二维码内容：qrPayload=JSON{t: ticketId}（紧凑）；web 用 qrcode 库渲染 dataURL；APP 相机扫码解析出 t 后调 info/confirm。
- [2026-11-19] ⑥ 轮询：web 登录页扫码 Tab 每 1.5s GET 一次（页面卸载/票终态停止）；scanned 状态显示「已在 APP 确认，请在手机上点击确认」——APP info 扫码即置 scanned（提示 APP 侧待确认），confirmed 携 token → web setSession（userId wire string）→ 进入主界面。
- [2026-11-19] ⑦ web 依赖：qrcode（登记 project.md）；APP 依赖：expo-camera（登记 project.md）。
- [2026-11-19] ⑧ 无迁移、无 WS 改动；既有端点零变化。

## API
### 创建扫码票据（POST /admin/v1/auth/qr-tickets，公开）
- 无 body；IP 频控；返回 `Result<QrTicketCreatedView>`，`record QrTicketCreatedView(String ticketId, String qrPayload, int expiresInSeconds)`（120s）。
### 轮询票据状态（GET /admin/v1/auth/qr-tickets/{ticketId}，公开）
- 返回 `Result<QrTicketStatusView>`，`record QrTicketStatusView(String status, AdminTokenIssued token)`（status∈created/scanned/confirmed/cancelled/expired；confirmed 时 token 非空；未知/过期 id → status=expired，token=null）。
### 扫码取信息（GET /admin/v1/auth/qr-tickets/{ticketId}/info，B 端认证）
- status created→scanned（幂等）；返回 `Result<QrTicketInfoView>`，`record QrTicketInfoView(String status, String createdAt)`；expired/cancelled → 业务失败码（QR_TICKET_EXPIRED/CANCELLED 族）。
### 确认（POST /admin/v1/auth/qr-tickets/{ticketId}/confirm，B 端认证）
- 原子单次；仅 scanned 可 confirm（created 直接 confirm 亦放行——扫码即确认的快速路径，实现者简化状态校验：非 confirmed/cancelled/expired 均可）；返回 `Result<AdminTokenIssued>`（wire userId string）；失败码 QR_TICKET_EXPIRED/CANCELLED/INVALID。
### 取消（POST /admin/v1/auth/qr-tickets/{ticketId}/cancel，B 端认证）
- 返回 `Result<Void>`（emptyAsSuccess）；幂等。
