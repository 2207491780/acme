# 消息通知闭环一期——站内信 + 通知公告 + WebSocket 实时推送 + 前端通知中心

## 背景

- 后端无站内信/邮件/WS 推送（SMS 仅为验证码通道），前端无通知中心、无实时能力——两端均为整域空白。
- 推送技术路线按用户裁决「多方案对比、性能优先」，TL 结论见确认记录①。
- 多实例扇出可用 Redis pub/sub：framework-cache `L1InvalidationBus` 已有同型先例；Kafka 已就绪但通知属低延迟小消息，pub/sub 足够。
- 网关为 Spring Cloud Gateway（WebFlux），原生支持 WebSocket 路由（需新增 `/ws/system/**` 路由）。
- 权限点种子惯例落 platform-system 迁移；公告正文富文本需前端富文本编辑器组件（选型见确认记录②）。

## API

> 统一响应体 `Result`；业务失败=`Result.code≠0`（HTTP 200）；错误码新增入 common-contract 错误码布局。

### 通知公告（platform-system，权限 `system:notice:*`）
- `POST /admin/v1/system/notices`：新建草稿（title/content 富文本 HTML）；`GET` 分页；`GET {id}` 详情；`PUT {id}` 编辑；`PUT {id}/publish` 发布（触发③扇出，重复发布幂等）；`PUT {id}/offline` 下线（裁决⑤：PUBLISHED→OFFLINE 幂等，OFFLINE 后可编辑/删除/再发布，再发布重新扇出）；`DELETE {id}` 软删（已发布需先下线——错误码 `NOTICE_PUBLISHED`；不存在=`NOTICE_NOT_FOUND`）。

### 站内信（platform-system）
- `POST /admin/v1/system/messages`：发送给指定用户（recipientIds/title/content），权限 `system:message:send`。
- `GET /admin/v1/system/messages`：我的收件箱分页（isRead 筛选）。
- `GET /admin/v1/system/messages/unread-count`：未读数。
- `PUT .../{id}/read`、`PUT .../read-all`：标记已读（他人消息不可操作——`MESSAGE_FORBIDDEN`）。

### 实时推送（WS `GET /ws/system/notify`）
- 握手带 token，验签失败拒绝；事件帧 `{type:"message:new", messageId, title}`；服务端 30s 心跳，超时回收；多实例经 Redis pub/sub 扇出到持有该用户会话的 pod。

## 验收标准（规格核心）

- AC-1 given 持有对应权限点 when 公告增删改查/发布/下线 then 各操作生效；无权限 then 统一拒绝 → 待回填
- AC-2 given 已发布公告 when 全员收件箱查询 then 每人一条对应 message（重复发布不重复扇出）→ 待回填
- AC-3 given 发送站内信 when 收件人查收件箱 then 可见；非收件人/发送者 then 不可见 → 待回填
- AC-4 given 标记已读/全部已读 when 查询 then read/read_at 落库、unread-count 递减/清零 → 待回填
- AC-5 given 非本人消息 when read then `MESSAGE_FORBIDDEN` → 待回填
- AC-6 given 有效 token when WS 握手 then 连接建立；无效 token then 拒绝 → 待回填
- AC-7 given 用户在线 when 向其发消息 then 该用户 WS 收到 message:new（端到端 <1s）→ 待回填
- AC-8 given 两实例各持同一用户连接 when 发消息 then 经 Redis pub/sub 两端均收到（多实例扇出）→ 待回填
- AC-9 given 连接静默超心跳周期 then 服务端断开并回收会话 → 待回填
- AC-10 given 前端 Header 铃铛 when 收到推送 then 红点+未读数实时更新；页面加载时拉取 unread-count 兜底 → 待回填
- AC-11 given 通知中心 when 打开 then 收件箱分页/全部已读/点击标记已读可用 → 待回填
- AC-12 given 公告管理页 when CRUD+富文本正文 then 行为对齐 CRUD 范本，富文本内容保存回显一致 → 待回填
- AC-13 given WS 断线 when 网络恢复 then 指数退避自动重连成功 → 待回填
- AC-14 given 全部完成 when 前端三件套+desktop check、后端 `mvn test` then 全绿 → 待回填
