# 主题偏好引擎与偏好抽屉一期

## 背景（钉死事实，均已实测）
- 视觉单源：`workspace/apps/frontend/packages/core/src/theme.ts`——`ACCENTS`（6 预设：cyan/blue/violet/magenta/amber/acid）+ `ACCENT_ORDER` + `ACCENT_COMPANIONS`（渐变伴随色）+ `ON_ACCENT`（统一纯黑保证对比度）+ `DARK_NEUTRALS/LIGHT_NEUTRALS` + `resolvePalette(theme)`；注释明确禁止端侧硬编码、Web/Mobile 均从此派生。
- web 侧映射：`workspace/apps/frontend/web/src/theme.ts` `buildTheme(settings)` → AntD ThemeConfig（algorithm 按 dark/default，token.colorPrimary 等），`themeSnapshot()` 供图表；消费点 `web/src/main.tsx` `<ConfigProvider theme={buildTheme(settings)}>`。
- 状态与持久化：`web/src/store/useStore.ts` zustand——settings 在 AppState blob 内，action `UPDATE_SETTINGS`（patch 合并），整 blob 持久化 localStorage key=`acme.frontend.ops.v1`（`packages/core/src/constants.ts`）。
- 现有外观入口：`web/src/pages/Settings.tsx` 整页设置，外观卡 4 项（深色 Switch/密度 Select/6 强调色圆点/动效 Switch），i18n 键域 `settings.appearance.*`（zh-CN/en-US 两份 `packages/core/src/i18n/resources/<locale>/settings.ts`）。
- core 小 store 惯例：`packages/core/src/store/persist.ts` `loadPersistedPreference/persistPreference`（运行时校验+异常降级内存态）；水印/锁屏是租户级（systemConfigStore），不在本期。
- mobile（`mobile/src/theme.ts` + SettingsScreen 主题分段）本期不动（对齐归 THEME-3）；desktop 套壳 web 产物自动继承。
- 外部输入必须运行时校验、失败不得覆盖原数据（编码规范）；当前无统一 lint 脚本。

## 交互规格
- 抽屉：AntD Drawer（右上），宽 ~360px，打开不阻塞页面；顶栏按钮带已选强调色圆点视觉提示。
- 所有修改即时生效（re-render 主题）并即时持久化（无「保存」按钮，对齐 vben 偏好面板交互）。
- 跟随系统：mode=system 时监听 prefers-color-scheme change 即时切换；用户手动选 light/dark 即脱离 system。
- 重置：确认弹窗 → 全部偏好回默认（出厂）。

## 验收标准（AC 是规格+追溯锚点；用例名由 tester 交付后回填）
core（preferences 引擎，vitest）：
- AC-1 given: 合法偏好（三态 mode/合法色值/密度/动效） when: schema 校验 then: 归一化通过且输出类型正确 → should_normalize_valid_preferences_when_parsed
- AC-2 given: 非法输入（未知 mode/非法色值/未知 accent 键） when: 校验 then: 逐字段降级默认不抛错、不覆盖既有合法字段 → should_fallback_to_defaults_when_preferences_invalid
- AC-3 given: 无 schemaVersion 的旧 settings（含 dark=true 旧语义） when: 迁移 then: 无损映射到新 shape（dark→mode=dark、accent/density/motion 保留）并写入版本号 → should_migrate_legacy_settings_losslessly_when_version_missing
- AC-4 given: mode=system 且系统主题变化 when: prefers-color-scheme 触发 then: 解析主题切换为对应 light/dark；mode≠system 时系统事件不改变用户选择 → should_follow_system_scheme_when_mode_is_system
web（偏好抽屉，vitest + 浏览器实测）：
- AC-5 given: 应用加载 when: 点击顶栏偏好入口 then: 抽屉打开且分组渲染（主题模式三选/强调色网格+自定义取色入口/密度/动效/恢复默认） → should_render_preference_drawer_groups_when_header_entry_clicked
- AC-6 given: 抽屉内切换 mode=system when: 提交 then: 主题即时按系统解析且刷新后保持 → should_apply_system_mode_instantly_and_persist_when_picked
- AC-7 given: ColorPicker 选自定义色 when: 应用 then: colorPrimary 即时生效（按钮/链接/选中态联动），派生语义色保持可读 → should_apply_custom_accent_instantly_when_color_picked
- AC-8 given: 依次选择预设色/密度/动效 when: 修改 then: 各项即时应用且 localStorage 持久化（重载保留） → should_apply_and_persist_each_preference_when_changed
- AC-9 given: 点击恢复默认 when: 确认 then: 全部偏好回出厂默认并即时生效 → should_reset_all_preferences_when_reset_confirmed
- AC-10 given: Settings 页 when: 渲染 then: 外观卡不再出现，其余设置卡（安全/租户配置等）不受影响 → should_remove_appearance_card_from_settings_when_migrated
- AC-11 given: zh/en 两语言 when: 抽屉渲染 then: 全键双语覆盖无裸 key → should_cover_all_drawer_strings_in_zh_and_en
- AC-12 given: 既有测试套件 when: 全量运行 then: 既有用例零回归（含 Settings 既有用例适配） → 既有套件回归口径（不新增断言文件，适配修改列 tester 清单）
