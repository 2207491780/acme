# 组织架构与数据权限——部门/岗位管理 + 角色-数据范围模型

## 背景

- platform-system 无 dept/position 实体（grep 全空）；RBAC 为平铺的用户-角色-菜单-权限。
- `framework-security` 已有 `@DataPermission` + 单 String scope + 单评估器（仅 audit 的 `AuditDataPermissionEvaluator` 落地），无角色-数据范围模型。
- 用户管理端点已存在（UsersPage），本 REQ 扩展其部门/岗位字段而非新建端点。
- 数据权限评估走查库模式（`PermissionDecisionService` 同款），评估器按 scope 类型扩展。

## API

> 统一响应体 `Result`；业务失败=`Result.code≠0`（HTTP 200）；错误码新增入错误码布局。

### 部门（platform-system，权限 `system:dept:*`）
- `GET /admin/v1/system/depts`：树形返回（含禁用态）；`POST`/`PUT {id}`/`DELETE {id}`：增改删（名称/父级/排序/状态）。

### 岗位（platform-system，权限 `system:position:*`）
- `GET /admin/v1/system/positions`：分页；`POST`/`PUT {id}`/`DELETE {id}`（名称/编码/状态；被用户引用的岗位删除拒绝——`POSITION_IN_USE`）。

### 角色数据范围（platform-system，权限 `system:role:scope`）
- `PUT /admin/v1/system/roles/{id}/data-scope`：设置 scope 枚举 + CUSTOM 时的 deptIds；仅超管或持有该权限点可操作。

### 用户扩展（既有端点改造，无新路径）
- 用户创建/编辑接受 `deptId`/`positionId`；用户列表支持 `deptId` 入参（含子部门递归）并按①模型过滤。

## 验收标准（规格核心）

- AC-1 given 部门树 when 增删改查 then 树形正确返回；删有子/有用户的部门 then `DEPT_HAS_CHILDREN`/`DEPT_HAS_USERS` → 待回填
- AC-2 given 岗位被用户引用 when 删除 then `POSITION_IN_USE`；无引用 then 删除成功 → 待回填
- AC-3 given 角色 scope=CUSTOM when 未传 deptIds then 校验拒绝；传合法 deptIds then `sys_role_dept` 落库 → 待回填
- AC-4 given 用户 A（scope=DEPT）when 查用户列表 then 仅见本部门；scope=DEPT_AND_CHILD then 含子部门；scope=SELF then 仅本人；scope=ALL then 全部 → 待回填
- AC-5 given 审计查询 when 角色为非 ALL scope then 结果按①模型过滤（既有 evaluator 改造后回归）→ 待回填
- AC-6 given 租户隔离 when 跨租户部门/用户 then 不可见不可操作（既有 TenantContext 回归）→ 待回填
- AC-7 given 无对应权限点 when 调任一新增端点 then 统一拒绝 → 待回填
- AC-8 given 前端部门树/岗位页/角色数据范围设置 when 操作 then 树选择、表单校验、权限显隐对齐 CRUD 范本 → 待回填
