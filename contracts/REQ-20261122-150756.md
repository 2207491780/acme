# 调度韧性（JOB-4）

## 背景（钉死事实，均已实测 2026-11-22 主树）
- 内核：SchedulerKernel tick() 三步（时间轮 drain/DB 兜底/PENDING 恢复扫描）；triggerSchedule=串行门（existsNonTerminalByDefinitionId）→SCHEDULE execution 插入（部分唯一索引 uk(def_id,fire_time) WHERE attempt=0 幂等）→submitDispatch→advanceNextFire；advanceResult CAS（FAILED→retryChain.spawnRetry）；patrol()=RUNNING 超 timeout_ms→TIMEOUT+孤儿 PENDING/DISPATCHED→DISPATCH_TIMEOUT+重试链。
- RetryChain.spawnRetry：RETRY execution（attempt+1、fire_time=now+initialIntervalMs 恒定间隔、继承 shardIndex/traceId）；耗尽仅 log.warn（「告警归 JOB-4」占位）；重试经 tick PENDING 恢复下发（进程重启不丢）。
- retry_policy jsonb={maxAttempts,initialIntervalMs}（空=不重试）；注释钉死「指数退避+jitter 归 JOB-4」。
- 分片现状=单发：JobDispatcher.shardContext() 恒 new ShardContext(0, shardTotal)（注释钉死「真扇出归 JOB-4」）；@JobHandler.shardable() 默认 false；SDK JobExecutionContext 已全量透传 shardIndex/shardTotal。
- ExecutionState CAS：PENDING/DISPATCHED→RUNNING/FAILED/CANCELLED；RUNNING→终态；TIMEOUT=独立终态（回调通道 ExecutionCallbackUseCase 仅收 RUNNING/SUCCESS/FAILED——TIMEOUT 上报被拒，靠巡检兜底）。
- 通知中心：sys_notice/sys_message（V8）；NoticeUseCase.publish() 全员扇出批插+TransactionEventPublisher→NotifyPushEvent→Redis pub/sub→WsSessionRegistry（+ExpoPushSender）；**无跨服务内部端点**（system internal 面无 notify）；全仓无外部服务接通知先例。
- 超时双源：sch_job_definition.timeout_ms（巡检判）vs @JobHandler.timeoutMs（SDK watchdog 中断+TIMEOUT 上报）——SDK 先上报 TIMEOUT 被回调拒，靠巡检兜底；无一致性校验。
- 管理面：AdminExecutionController 已有 state 过滤查询（失败检索可复用）；前端执行历史 Tab 已可过滤 state=FAILED；站内信 UI 既有。

## 确认记录（契约的权威解释；只存结论条目）
- [2026-11-22] ① 用户批量授权（同 REQ-010725 ①）；范围=规划 JOB-4。
