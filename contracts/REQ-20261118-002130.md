# 单体/分布式双形态打包（acme-bootstrap）

## 背景
- 已实测事实（TL 探索 2026-11-18）：三服务 Application 注解——auth `@EnableFeignClients(clients={AuthProfileClient,AuthorizationClient,TenantClient,SystemConfigClient})`＋@Bean UserTokenIssuer/BCryptPasswordEncoder；system `clients={TenantSessionRevokeClient}`；infra `clients={AuthorizationClient,DataScopeClient,LoginLogCleanupClient}`（LoginLogCleanupClient 声明在 infra 侧调 auth）；全部显式 clients 数组无 basePackages。Flyway：三服务均缺省 `classpath:db/migration`（无显式 locations），default-schema 各自 platform_{auth|system|infra}，历史表随 schema 隔离，版本号跨服务各自协调（system 至 V19、infra 至 V18、auth 至 V6）——**单 JVM classpath 合流后同路径迁移会互相污染，必须 per-service 子目录化**（Flyway checksum 与路径无关，挪目录不破坏既有历史）。雪花：SnowflakeIdGenerator 非静态单例，AuditSupport 懒建静态 volatile defaultIds（workerId 缺失显式失败），键 `acme.flex.id.worker-id`（auth=1/system=2/infra=3）。stream/Kafka 仅 infra（auditEventOut/auditEventIn→infra-audit-events＋DLQ；无 Kafka 时 DlqConfigValidator+binder 阻断启动，规避开关 `acme.stream.enabled=false`＋`acme.audit.enabled=false` 有测试先例）；AuditEventMqSink 的 MessageSender 为 ObjectProvider 缺席降级空操作；auth/system 审计仅 Spring 事件。调度仅 infra 4 job（ShedLock JdbcTemplateLockProvider 表 shedlock_locks 在 infra schema；framework-job AUTO 模式）；LoginLogRetentionCleanupJob 经 Feign 调 auth 清理端点。WebSocket 全在 system（channel `platform-system:notify:ws`；NotifyTokenVerifier 为 servlet 侧重写先例）。令牌验签：UserTokenIssuer（platform-auth，TokenKeys.hmacKey 构造）；framework-gateway DefaultUserTokenVerifier 纯 jjwt 可复用但类在 WebFlux 模块；NotifyTokenVerifier 同语义 servlet 先例。InternalTokenAuthFilter(InternalTokenVerifier, List<String> publicPaths) 构造注入（SecurityProperties acme.security.public-paths）。public-paths 合并集=actuator + auth 8 条 + system /ws/system/**。Dockerfile ARG MODULE_PATH 参数化（先 install 父 POM 再 -pl module -am package）；cd.yml build 循环 `"MODULE_PATH 镜像名"` 对；deploy.sh 清单循环（minio 已存在性判断）。CI 门禁：分布式形态为默认与现有测试基线，单体验证不要求覆盖全部集成测试。
- 用户授权约束：分布式为默认形态；单体为可选打包路径（本地联调/小部署）；MinIO 无环境继续跳过。

## 确认记录（契约的权威解释；只存结论条目，禁存对话原文）
- [2026-11-18] ① 迁移目录 per-service 化：三服务迁移移至 `db/migration/{auth|system|infra}`；各服务 main/test yml 增 `spring.flyway.locations: classpath:db/migration/<域>`；测试类 DynamicPropertyRegistry 不需联动（locations 继承 yml）；分布式行为零变化（每服务只扫自己目录）。BACKEND.md 增迁移目录归属与版本协调说明。
- [2026-11-18] ② bootstrap 装配：新模块 `acme-bootstrap`（依赖三 *-service jar；不依赖 framework-gateway/WebFlux/scg）。`MonolithApplication`：`@SpringBootApplication(scanBasePackages="com.acme.platform")`＋`@Import({PlatformAuthApplication,PlatformSystemApplication,PlatformInfraApplication})`——**Application 类作为普通配置类导入**，其 `@EnableFeignClients(clients=…)` 在单体改由「Feign 惰性＋@Primary 本地适配器」化解：`spring.cloud.openfeign.lazy-attributes-resolution: true`＋6 个 @Primary 本地适配器 bean（LocalAuthProfileClient/LocalAuthorizationClient/LocalTenantClient/LocalSystemConfigClient/LocalDataScopeClient/LocalTenantSessionRevokeClient＋LocalLoginLogCleanupClient，共 7 个，各构造注入对应本域 UseCase/Repository 直调），Feign bean 因惰性永不实例化。若惰性开关在当前 Spring Cloud 版本不可用，退路=bootstrap 排除 Feign 自动配置并以 `@ComponentScan(excludeFilters)` 不扫 Application 类、手工 @Import 三服务的非 Application 配置类（实现者二选一，报告注明）。
- [2026-11-18] ③ 中间件合并：单 application.yml——datasource 一份（PG，currentSchema 用 search_path 覆盖三 schema）；**Flyway 手动三实例**（`spring.flyway.enabled=false`，bootstrap 三个 @Bean Flyway：同一 dataSource，schemas/defaultSchema 各自、locations 各自目录、placeholder auth 三种子密码保留）；`acme.flex.id.worker-id=1`（单 JVM 一份静态单例）；Redis 一份（键前缀天然不冲突）；Nacos 软依赖（无 spring.config.import nacos、`spring.cloud.nacos.discovery.enabled=false`）；stream 关闭（`spring.cloud.stream.enabled=false`＋`spring.cloud.function.definition` 清空）＋**本地审计 sink**：bootstrap 提供 @Primary AuditEventSink 直调 AuditIngestUseCase（同 JVM 去掉 MQ 回环；去重门 M-12 语义保留）。
- [2026-11-18] ④ 边缘认证（无网关形态）：bootstrap 新增 servlet 过滤器 `BootstrapAuthFilter`（order=InternalTokenAuthFilter 之前）：用 TokenKeys+jjwt 复用实现（抽 DefaultUserTokenVerifier 逻辑到 framework-security 的无 WebFlux 类 `UserTokenAccessVerifier`，gateway 的 DefaultUserTokenVerifier 改为委托/继承它——避免双实现漂移）；校验 access 令牌→绑定 X-Acme-* 内部头→放行给 InternalTokenAuthFilter 链；`/admin/v1/auth/**` 公开路径与 ws 握手豁免；撤销检查同 JVM 直调 SessionRedis.isRevoked（FAIL_OPEN 口径同网关）。rate-limit/XSS/灰度过滤器单体不携带（网关职责，文档注明能力差异）。
- [2026-11-18] ⑤ 配置与文档：bootstrap `application.yml`（port 9680）+ `application-monolith.yml` 语义合并（auth/system/infra 三份键并集手工维护，重复键取一；public-paths 并集）；`README-bootstrap.md` 或 BACKEND.md 章节：启动命令（env 同分布式）＋能力差异（无网关过滤器集/限流/灰度）＋Nacos/Kafka 可选性。BACKEND.md 增「双形态」小节。
- [2026-11-18] ⑥ 打包与部署：Dockerfile 增加 `ARG PACKAGE=module`（module=现行为；bootstrap=构建 acme-bootstrap）；cd.yml build 循环加 `PACKAGE_MODE` 输入（workflow_dispatch input 默认 distributed；monolith 时构建 `acme-bootstrap→acme-monolith` 镜像且跳过四服务镜像）；deploy.sh 无需改（清单驱动已兼容）；env-stack 增 `k8s/base/acme-monolith.yaml`（Deployment+SVC 9680，镜像占位）＋`overlays/monolith/kustomization.yaml`（替换四服务 resources 为 acme-monolith，postgres/redis/nacos 保留、gateway/web 保留 web 去 gateway）——**交付不部署**（部署冒烟属后续可选，Redis 租约口径）。
- [2026-11-18] ⑦ 验证口径：单体验证=本地以 monolith 形态起 acme-bootstrap（PG/Redis 经隧道）→ 登录/系统配置/文件上传三链路冒烟＋网关特有端点（/docs 聚合）预期缺失记录；分布式回归=既有全量 mvn test（locations 改造后全绿）＋三服务照常启动。CI 不新增作业（打包形态由 dispatch 参数决定）。
