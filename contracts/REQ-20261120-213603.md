## API
### 菜单树查询（GET /admin/v1/system/menus）——既有接口新增可选 query 参数
- 新增可选参数（全部可选；提供多个时 AND 语义）：
  - `keyword`：字符串；对 menuName / path / permissionCode 做不区分大小写的包含匹配，任一字段命中即算命中
  - `menuType`：DIRECTORY|MENU|BUTTON，精确匹配
  - `status`：ENABLED|DISABLED，精确匹配
  - `visible`：true|false，精确匹配
- 无参数 → 行为与现状完全一致（全量树）
- 命中语义：满足全部已提供条件的节点=命中节点；返回树=命中节点∪其全部祖先（保持父子层级组装）；命中节点的子孙不自动带出
- 返回：`Result<List<AdminMenuView>>`（树形结构、DTO、排序 sortOrder asc/id asc 均不变）；page/size 沿用现状（可选携带、不分页）；权限沿用 MENU_LIST
- 服务层集成点（TL 收口，防并行漂移；路由裁决见流程状态 round 1）：`MenuUseCase` 新增 `listFiltered(String keyword, MenuType menuType, EnableStatus status, Boolean visible)`，返回平铺 `List<SysMenu>`（命中节点∪其全部祖先，sortOrder asc/id asc；命中节点子孙不自动带出）；`MenuController` 组树复用既有 `EntityViews.menuTree(...)`：**四参数全空→`listAll()` 现状路径；任一参数非空→`listFiltered(...)`**。`listAll()` 原签名与语义不动。
- 失败：非法枚举值→HTTP 400＋Result 信封 WebError.BAD_REQUEST（框架既有翻译器行为）；成功 code=0
- 不新增错误码；POST/PUT/DELETE/GET /{id} 等其余接口不动
