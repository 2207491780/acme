# 管理端八域功能缺陷批量修复

## 背景（只写实现者不知道的事实；细节证据见 .ai-tmp/req-bugfix/ 四份调查报告）

- **空体报错机制**：`StandardResponseAdvice` 对 void 返回类型豁免统一信封（框架设计行为）→ HTTP 200 + 0 字节；前端 `client.ts` 对未声明 `emptyAsSuccess` 的 2xx 空体抛 `EMPTY_BODY`「接口无响应体（HTTP 200）」。mock 与真实后端两口径并存是测试未拦住的原因。仓库信封先例：`DeptController.delete`/`PositionController`/`RoleController.updateDataScope` 显式 `Result.ok(null)`。
- **雪花 ID 精度丢失**：主键全部为雪花（19 位 > 2^53）；`LongToStringModule` 读侧字符串无损、反序列化兼容字符串输入；**提交侧** `api/system.ts` userCreate/userUpdate/`userBindRoles`/`roleDataScope` 及 `DeptsPage`/`RolesPage` 的 `Number()` 转换破坏精度 → `DEPT_NOT_FOUND`。mock/测试用小 ID，dev 不复现。真实环境无任何 sys_dept/sys_position 种子（V1-V32 已核对），UI 创建行全是雪花 ID。
- **树形叶子无效展开图标**：本仓库树响应契约 children 恒为数组（叶子 `[]`，DTO 兜底归一）；antd/rc-table 以「行对象存在 children 键」truthy 判树形 → 空数组叶子渲染无效图标。后端改契约影响面大，**前端展示层剥空 children** 为定案。TreeSelect 同型风险点 3 处需实测（角色授权抽屉菜单树/套餐表单菜单树/父租户下拉）。
- **角色 parentId 三态契约**（`AdminRoleUpdate` javadoc）：null=不调整、0=移为根、>0=改父；前端清空发 null + 三元 falsy 吞 0，双层失效；mock PUT roles 处理器不读 parentId。后端零改动，前端传哨兵 0。真后端根角色 wire `parentId=0` 与契约「根归一 null」不符（F7，本次后端归一）。
- **TabKeepAlive 页签保活**：切签不卸载、激活不自动重取；租户页套餐/模板/租户树目录全部 `useEffect([])` 挂载拉一次，`TenantPackagesPage` 菜单树/能力目录用 `useRef` 缓存页签存续期永不失效。
- **数据模型现状**：`sys_dict_type`/`sys_dict_item` 无 kind/parent 列（树形字典=纯增量 DDL）；`sys_permission` 已有 `http_method`/`http_path`（87 条种子路径 100% 可解析出服务段），无 service 列；`sys_tenant` 已有 parent_id/level（V30）且新建/编辑表单已有父租户 TreeSelect（字段在，疑似树接口失败静默降级成空候选）；模板 roleKey/roleName/permissionCodes 纯手填（roles/permissions 目录接口已在、未消费）。
- **权限面**：`system:position:list` 等组织权限码种子仅绑超管（V9），非超管账号岗位下拉 403 后前端静默降级为空——用户表单/筛选的目录消费改走新端点（挂 `system:user:list`）。
- **文件管理**：前端路由/菜单种子/权限种子/mock/后端 Controller/网关路由五环闭合无代码断点；疑断在运行环境——platform-infra 启动强依赖 `ACME_STORAGE_LOCAL_ROOT_DIR`（无默认值 fail-fast），k8s base 不注入（由 overlay/secrets 负责）；dev 默认开 MSW 会造成假联调。
- **Flyway 部署纪律**：`out-of-order` 未开启（默认 false），application.yml 明文「并行分支的低段位迁移不得晚于高段位上线」；V33/V34 已被 REQ-20261125-001737/001738（confirmed 未开工）预留，本需求取 V35/V36，**合并/部署顺序必须晚于 V33/V34**（合并时协调，见流程状态）。

## API

### GET /admin/v1/system/user-form-options（新增）
- 权限：`system:user:list`（既有码，**无新权限点种子**）；`@RequirePermission` + 只读。
- 返回：`Result<UserFormOptionsView>`，`{ deptTree: AdminDeptView[]（树形）, positions: AdminPositionView[], roles: AdminRoleView[] }`，目录全量（roles/positions 经仓储全查，规模受控）。
- 消费方：用户管理页筛选/表单/列名称映射；替代该页对 `system:dept:list`/`system:position:list`/角色分页接口的依赖。
- 网关：`/admin/v1/system/** → platform-system` 既有路由，无需改。

### void 端点信封化（wire 变更，9 处，path 全部不变）
- `CredentialController.resetPassword`、`UserController.delete/updateStatus/bindRoles`、`TenantController.updateStatus`、`TenantQuotaController.saveQuota`、`DictController.dictTypeDelete/dictItemDelete` 改返回 `Result<Void>` + `Result.ok(null)`；失败信封错误码沿用既有枚举。
- mock 同步 `ok(null)`（users 3 处 `empty()`、tenant status `empty()`、quota `ok(tenantView)` 错形、dict 2 处 `empty()`）；auth resetPassword mock 已是信封。

### 字典树形（V35 迁移）
- `sys_dict_type` + `dict_kind varchar(16) NOT NULL DEFAULT 'FLAT'`（FLAT|TREE）；`sys_dict_item` + `parent_id bigint NULL`。
- 条目读取：kind=FLAT 现状平铺不变；kind=TREE 返回嵌套 children 树（DTO 新形状，children 恒数组）。
- 条目写入（TREE）：父条目必属同字典类型、存在、非自身/子孙（防环）；FLAT 类型提交 parentId → `PARAM_INVALID`。
- 平铺行为零变化（既有数据迁移后全为 FLAT 默认值）。

### sys_permission.service（V36 迁移）
- + `service varchar(32) NULL`；回填：`split_part(http_path,'/',4)` 为主（path 第 4 段），`permission_code` 首段兜底，`content→contents` 归一。
- `AdminPermissionView` + `service`；**Create/Update DTO 不加**（service 只由迁移维护——与「flyway 维护目录」口径一致）；列表筛选不加（最小改动）。

### AdminTenantInitRequest.templateCode 必填化
- 后端校验：blank → `PARAM_INVALID`；`tenantCreate` 端点保留不退役（前端创建分支不再调用）。
